# Plan: Phase 6 RecordSet charts and adaptive views

**Status:** Draft
**Source Feature:** chat-recordset-adaptive-charts
**Date:** 2026-09-21
**Owner:** codex
**Supersedes:** —

## Summary

Add incremental RecordSet analysis, pure chart inference and NTCharts rendering to the existing terminal Chat UI, with adaptive Table/Charts/Current row presentations. The original request is preserved at `docs/chat-phase6-original-prompt.md`.

## Approach

Journey: ask for Chinook invoices → the DALgo-backed secure read returns real invoice rows and incremental statistics → Chat stores the immutable result → the user focuses its table, opens Charts and sees the highest-ranked real-data visualization → the user chooses a second candidate and gets a different but deterministic chart → the user returns to Table, sorts it, and the same source row remains selected → Current row displays that exact invoice and scrolls through its fields → resizing across the 40-cell threshold moves the inspector beside or in place of the table without losing state → exiting and reopening restores the result and charts without rerunning the invoice query. Each arrow has an observable UI or stored-data assertion in the real-terminal acceptance run.

1. Extend `secureread.Result` with data-layer statistics and feed an accumulator from the existing `collectRows` loop. Bound distinct/frequency and date/measure aggregate maps, clearly flag incomplete statistics, and preserve old snapshot compatibility through the typed encode/decode path. The `RunSnapshot` policy round-trip normalizes booleans/decimals/dates through SQLite; finish type-sensitive statistics from the restored typed evidence inside that existing restoration pass, so chart inference does not mistake SQLite representations for source types. Test both ordinary collector and snapshot boundaries first.
2. Define pure `ChartSpec`, candidate scoring and deterministic ordering in Chat, independent of terminal size and NTCharts types. Build Top-10 category count bars, chronological date count/sum lines, and scatter only if the NTCharts v2 API makes it cheap. Test nulls, ties, IDs, booleans, high cardinality, numeric and date variations.
3. Add a small NTCharts v2 adapter for the supported specs. Pin a compatible version in `go.mod`; verify its Bubble Tea v2 integration and render dimensions with focused tests. No image protocol or additional chart framework.
4. Extend each `gridState` with Table/Charts/Current-row view state, selected candidate and active subpane focus. Keep `bubble-table` as the table owner, table-selected source row as inspector identity, and `viewport.Model` as the inspector scroll owner. Before sorting, capture `GridModel.SourceRows[rowIndex]`; after sorting remap the cursor to that same source-row ID and make the inspector follow it. Test this with duplicate sort values. Add compact header/candidate navigation and unambiguous keybindings while preserving JOIN/workspace/composer controls.
5. Compute a pure adaptive layout from actual chat-pane width, preferred/useful table width, gap/borders and 40-cell minimum secondary width. Render table+secondary wide and secondary-only narrow; rebuild safely on terminal/workspace resize, preserving row/chart/inspector state. Test boundary widths and repeated crossing.
6. Update status/help and relevant docs. Run focused and broad Go tests, lint/build, persisted restart checks and one uninterrupted real Chinook/cheap-provider TTY journey: query invoices, view and switch charts, return to and sort the table while retaining the selected source row, open and scroll its inspector, resize in both directions, exit, restart, and confirm restoration without a historical query. Record expected versus observed for each stage. Independently review behavior, complexity, licensing and UX; fix findings, then WB-land and verify remote main, CI, release if triggered, and worktree cleanup.

Review decisions: candidate inference runs only on finalized results to avoid reorder churn; statistics never depend on view width; incomplete bounded frequencies never claim exact Top 10; older snapshots are analyzed as their typed rows are decoded; no query is issued merely to create a chart; row values stay in DataTug's structured result; no chart is sent to or generated by the model.
